# S09. Proyecto integrador: planificación y prototipado de una interfaz

## 1. Introducción

En las sesiones anteriores hemos trabajado comunicación visual, percepción, composición, tipografía, color, identidad, componentes, bocetado, mapas de navegación, wireframes y prototipos.

En esta sesión integrarás esos conocimientos en una propuesta coherente. El objetivo es demostrar que puedes planificar una interfaz antes de desarrollarla y justificar las decisiones que has tomado.

Este proyecto es una actividad de diseño y planificación. No consiste todavía en programar la web.

## 2. Objetivos

- Definir el propósito de una interfaz.
- Identificar sus usuarios y tareas principales.
- Organizar la navegación.
- Proponer una identidad y una guía de estilo inicial.
- Diseñar wireframes de las pantallas principales.
- Crear un prototipo navegable.
- Justificar las decisiones de comunicación visual.

## 3. Enunciado del proyecto

Diseña la planificación de una aplicación web para una **biblioteca digital**. La propuesta debe permitir:

- Consultar novedades.
- Buscar libros.
- Ver la información de un libro.
- Acceder a una cuenta personal.
- Consultar préstamos o solicitudes.

Puedes adaptar el contenido, pero debes mantener las tareas principales.

## 4. Fase 1. Definición del proyecto

Redacta una ficha con:

- Nombre provisional.
- Objetivo principal.
- Usuarios a los que se dirige.
- Necesidades que pretende resolver.
- Cinco tareas que debería poder realizar el usuario.

Evita descripciones vagas como «ser una web moderna». Define qué problema resuelve.

## 5. Fase 2. Mapa de navegación

Crea un mapa que incluya, como mínimo:

- Inicio.
- Catálogo.
- Resultados de búsqueda.
- Ficha del libro.
- Mi cuenta.
- Préstamos o solicitudes.
- Ayuda o contacto.

Organiza las secciones en niveles y añade accesos cruzados si son necesarios.

Comprueba que las tareas definidas en la fase 1 tienen una ruta.

## 6. Fase 3. Identidad y guía de estilo

Define una propuesta inicial que incluya:

### Identidad

- Nombre y logotipo provisional o representación textual.
- Idea que debe transmitir la marca.
- Estilo visual general.

### Color

Define al menos seis roles y sus valores HEX: principal, secundario, fondo, superficie, texto y estado.

### Tipografía

Define familia principal y niveles: título, título de sección, subtítulo, párrafo y texto auxiliar.

### Componentes

Documenta como mínimo:

- Botón principal.
- Botón secundario.
- Campo de búsqueda.
- Tarjeta de libro.
- Mensaje de estado.

Incluye la función y las reglas de uso de cada uno.

## 7. Fase 4. Wireframes

Diseña al menos tres pantallas:

1. Inicio.
2. Catálogo o resultados.
3. Ficha del libro.

Los wireframes deben mostrar estructura, agrupación, navegación, contenido y acciones. No es necesario que tengan el acabado visual definitivo.

## 8. Fase 5. Prototipo

Conecta las pantallas para simular este recorrido:

1. El usuario entra en Inicio.
2. Accede al Catálogo.
3. Busca o selecciona un libro.
4. Consulta su ficha.
5. Inicia una solicitud o accede a la cuenta.

El prototipo puede simular la operación; no es necesario que gestione datos reales.

## 9. Fase 6. Revisión

Revisa la propuesta con esta lista:

- ¿Se entiende el objetivo?
- ¿La navegación tiene una estructura lógica?
- ¿Las tareas principales tienen una ruta?
- ¿Los elementos relacionados están agrupados?
- ¿Existe jerarquía visual?
- ¿La tipografía permite leer con comodidad?
- ¿La paleta tiene roles definidos?
- ¿Los componentes mantienen coherencia?
- ¿El prototipo permite completar el recorrido?
- ¿Has detectado y corregido problemas?

## 10. Entregables

Entrega una carpeta o documento organizado con:

1. Ficha de definición del proyecto.
2. Mapa de navegación.
3. Guía de estilo inicial.
4. Wireframes de tres pantallas.
5. Prototipo navegable.
6. Memoria breve con las decisiones y mejoras realizadas.

Nombra los archivos de forma clara y mantén una versión final identificable.

## 11. Criterios de calidad del trabajo

| Aspecto | Qué se espera |
|---|---|
| Comunicación visual | La propuesta tiene un objetivo comprensible |
| Organización | La información está agrupada y jerarquizada |
| Identidad | Los recursos visuales mantienen coherencia |
| Guía de estilo | Los valores y reglas están documentados |
| Navegación | Las secciones y rutas son comprensibles |
| Wireframes | Las pantallas muestran estructura y acciones |
| Prototipo | Se puede recorrer la tarea principal |
| Justificación | Las decisiones se explican con argumentos |

## 12. Errores que debes evitar

- Empezar por los colores sin definir el objetivo.
- Diseñar pantallas sin mapa de navegación.
- Incluir botones que no conducen a ninguna parte.
- Utilizar estilos diferentes para componentes equivalentes.
- Entregar wireframes sin identificar sus zonas.
- Presentar como funcional una operación que solo está simulada.
- No justificar las decisiones.

## 13. Reflexión final

Responde por escrito:

1. ¿Qué decisión de diseño ha sido más importante?
2. ¿Qué problema detectaste durante la revisión?
3. ¿Qué cambiaste y por qué?
4. ¿Qué parte de la planificación te ha resultado más difícil?
5. ¿Qué comprobarías con usuarios reales antes de desarrollar la aplicación?

- [ ] He definido colores y tipografías.
- [ ] He descrito componentes.
- [ ] He creado al menos tres wireframes.
- [ ] He conectado las pantallas en un prototipo.

- [ ] He justificado las decisiones y mejoras.
